# 0xBF / 0x10 - Object properties and equipment info
Direction: both. Size: C->S fixed 9 bytes; S->C variable (minimum 17).
Purpose: C->S requests the properties of an object (old format, before 0xD6); S->C describes the attributes of an equipment item (name, crafter, identification state, attributes).

C->S:

| Offset | Size | Type | Field | Description |
|---|---|---|---|---|
| 0 | 1 | u8 | id | 0xBF |
| 1 | 2 | u16 | length | 9 |
| 3 | 2 | u16 | subcommand | 0x0010 |
| 5 | 4 | u32 | serial | Object queried |

S->C:

| Offset | Size | Type | Field | Description |
|---|---|---|---|---|
| 0 | 1 | u8 | id | 0xBF |
| 1 | 2 | u16 | length | Total size |
| 3 | 2 | u16 | subcommand | 0x0010 |
| 5 | 4 | u32 | serial | Item |
| 9 | 4 | u32 | nameCliloc | Cliloc of the name (0 = none) |
| 13 | 6+n | optional | crafter | `i32 -3`, `u16 n`, `n` bytes ASCII (crafter name) |
| ... | 4 | optional | unidentified | `i32 -4` when the item is not identified |
| ... | 6 per attribute | list | attributes | `u32 cliloc` + `i16 charges` (-1 = no charges) |
| end | 4 | i32 | terminator | -1 (0xFFFFFFFF) |

Notes:
- Fixed order: name, crafter (if present), unidentified marker (if present), attributes, terminator -1.
- On receipt, ClassicUO shows the text and then requests the item's mega cliloc (0xD6 or this same old command, depending on the version).
- Source-X: the C->S format also exists with the payload `u32 serial` (old tooltip version). Source-X in S->C uses this same id with `u32 serial` + `u32 version` (13 bytes) to announce the tooltip revision in the old format (see 0xDC for the new format).
