# 0xBF / 0x06 - Party commands
Direction: both. Size: variable (depends on the command).
Purpose: manages the group (party): member list, invitation, messages and options.

| Offset | Size | Type | Field | Description |
|---|---|---|---|---|
| 0 | 1 | u8 | id | 0xBF |
| 1 | 2 | u16 | length | Total size |
| 3 | 2 | u16 | subcommand | 0x0006 |
| 5 | 1 | u8 | command | Sub-subcommand (table below) |
| 6 | ... | ... | payload | Depends on the command |

Sub-subcommands:

| command | Name | Direction | Payload after `command` | Total size |
|---|---|---|---|---|
| 0x01 | Add member / member list | C->S: invite request; S->C: list | C->S: `u32 serial` (the client sends 0 and the server replies with a target cursor). S->C: `u8 count` + `u32[count] serials` (the first one is the leader) | C->S 10; S->C `7 + 4*count` |
| 0x02 | Remove member | C->S: removal request; S->C: notification | C->S: `u32 serial`. S->C: `u8 count` (remaining members) + `u32 removed` + `u32[count] serials` | C->S 10; S->C `11 + 4*count` |
| 0x03 | Private message | both | `u32 serial` (C->S: recipient; S->C: sender) + null-terminated UTF-16BE text | `10 + 2*(n+1)` |
| 0x04 | Public message (to the whole group) | both | C->S: null-terminated UTF-16BE text. S->C: `u32 sender serial` + null-terminated UTF-16BE text | C->S `6 + 2*(n+1)`; S->C `10 + 2*(n+1)` |
| 0x06 | Allow looting of my body | C->S | `u8 canLoot` (0 or 1) | 7 |
| 0x07 | Invitation received | S->C | `u32 serial` of the leader who invited | 10 |
| 0x08 | Accept invitation | C->S | `u32 serial` of the leader | 10 |
| 0x09 | Decline invitation | C->S | `u32 serial` of the leader | 10 |

Notes:
- When the server sends a removal list with `count <= 1`, the client dissolves the group. If the removed serial is the player's own or the leader's (position 0), the client also clears the whole group.
- ServUO uses `command 0x02` with `count = 0` and the player's serial for "empty group" (11 bytes).
- Source-X defines `command 5` (Disband) in the enum, but the actual client flow dissolves the group by removing the leader; this value does not appear in ServUO/ModernUO/ClassicUO.
- Removing the leader is equivalent to undoing the group on the client.

## Example

C->S, the player asks to invite someone (the client sends serial 0 and the server returns the target cursor):

```
BF 00 0A 00 06 01 00 00 00 00
```

| Bytes | Meaning |
|---|---|
| `BF` | id |
| `00 0A` | length = 10 |
| `00 06` | subcommand = party |
| `01` | command = add |
| `00 00 00 00` | serial = 0 |

S->C, the server sends the group list with two members (the first is the leader, serials 0x00000001 and 0x00000002):

```
BF 00 0F 00 06 01 02 00 00 00 01 00 00 00 02
```

`00 0F` = 15 = 7 + 4*2; `01` = command list; `02` = count; followed by the two serials.

S->C, invitation received from leader 0x00000001:

```
BF 00 0A 00 06 07 00 00 00 01
```
