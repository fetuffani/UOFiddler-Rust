# 0xBF / 0x19 - Extended stats
Direction: server -> client. Size: depends on the variant (11, 12 or 17 bytes).
Purpose: four uses that share the subcommand, distinguished by the `version` byte at offset 5.

| Offset | Size | Type | Field | Description |
|---|---|---|---|---|
| 0 | 1 | u8 | id | 0xBF |
| 1 | 2 | u16 | length | Total size |
| 3 | 2 | u16 | subcommand | 0x0019 |
| 5 | 1 | u8 | version | 0, 2 or 5 |
| 6 | 4 | u32 | serial | Mobile |
| 10 | ... | ... | payload | Depends on `version` |

Variants:

| version | Name | Payload after `serial` | Total size |
|---|---|---|---|
| 0 | Bonded status | `u8 dead` (1 = dead/ghost, 0 = alive) | 11 |
| 2 | Attribute locks | `u8 updateGump` (0) + `u8 lockBits` | 12 |
| 5 | Locks (EC client) or statue animation | See below | 12 or 17 |

`lockBits` (versions 2 and 5): `(strLock << 4) | (dexLock << 2) | intLock`, where each lock is 0 = up, 1 = down, 2 = locked.

Version 5, statue animation (17 bytes): after the serial come `u8 0`, `u8 0xFF`, `u8 status`, `u16 animation`, `u16 frame`. ClassicUO distinguishes this form by the second byte being 0xFF; any other value is treated as the version 2 lock format. If `status`, `animation` and `frame` are all 0, the client treats it as variant 0 (bonded).

Notes: ServUO sends version 5 in place of 2 for Enhanced Client. ServUO's `BoatDriverLock` packet uses version 5 with 19 bytes (body after the serial: `00 FF 00 00 04 00 00 00 00`); the semantics of these fields are not specified.
