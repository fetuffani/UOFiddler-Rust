# 0xBF / 0x06 - Comandos de party
Direção: ambas. Tamanho: variável (depende do comando).
Finalidade: gerencia o grupo (party): lista de membros, convite, mensagens e opções.

| Offset | Tamanho | Tipo | Campo | Descrição |
|---|---|---|---|---|
| 0 | 1 | u8 | id | 0xBF |
| 1 | 2 | u16 | length | Tamanho total |
| 3 | 2 | u16 | subcommand | 0x0006 |
| 5 | 1 | u8 | command | Sub-subcomando (tabela abaixo) |
| 6 | ... | ... | payload | Depende do comando |

Sub-subcomandos:

| command | Nome | Direção | Payload após `command` | Tamanho total |
|---|---|---|---|---|
| 0x01 | Adicionar membro / lista de membros | C->S: pedido de convite; S->C: lista | C->S: `u32 serial` (o cliente envia 0 e o servidor responde com um cursor de alvo). S->C: `u8 count` + `u32[count] serials` (o primeiro é o líder) | C->S 10; S->C `7 + 4*count` |
| 0x02 | Remover membro | C->S: pedido de remoção; S->C: notificação | C->S: `u32 serial`. S->C: `u8 count` (membros restantes) + `u32 removido` + `u32[count] serials` | C->S 10; S->C `11 + 4*count` |
| 0x03 | Mensagem privada | ambas | `u32 serial` (C->S: destinatário; S->C: remetente) + texto UTF-16BE terminado em nulo | `10 + 2*(n+1)` |
| 0x04 | Mensagem pública (para todo o grupo) | ambas | C->S: texto UTF-16BE terminado em nulo. S->C: `u32 serial remetente` + texto UTF-16BE terminado em nulo | C->S `6 + 2*(n+1)`; S->C `10 + 2*(n+1)` |
| 0x06 | Permitir saque do meu corpo (loot) | C->S | `u8 canLoot` (0 ou 1) | 7 |
| 0x07 | Convite recebido | S->C | `u32 serial` do líder que convidou | 10 |
| 0x08 | Aceitar convite | C->S | `u32 serial` do líder | 10 |
| 0x09 | Recusar convite | C->S | `u32 serial` do líder | 10 |

Notas:
- Quando o servidor envia uma lista de remoção com `count <= 1`, o cliente dissolve o grupo. Se o serial removido é o próprio jogador ou o líder (posição 0), o cliente também limpa todo o grupo.
- ServUO usa `command 0x02` com `count = 0` e serial do jogador para "grupo vazio" (11 bytes).
- O Source-X define `command 5` (Disband) no enum, mas o fluxo real do cliente dissolve o grupo removendo o líder; o valor não aparece em ServUO/ModernUO/ClassicUO.
- Remoção do líder equivale a desfazer o grupo no cliente.

## Exemplo

C->S, o jogador pede para convidar alguém (o cliente envia o serial 0 e o servidor devolve o cursor de alvo):

```
BF 00 0A 00 06 01 00 00 00 00
```

| Bytes | Significado |
|---|---|
| `BF` | id |
| `00 0A` | length = 10 |
| `00 06` | subcommand = party |
| `01` | command = adicionar |
| `00 00 00 00` | serial = 0 |

S->C, o servidor envia a lista do grupo com dois membros (o primeiro é o líder, serial 0x00000001 e 0x00000002):

```
BF 00 0F 00 06 01 02 00 00 00 01 00 00 00 02
```

`00 0F` = 15 = 7 + 4*2; `01` = command lista; `02` = count; depois os dois serials.

S->C, convite recebido do líder 0x00000001:

```
BF 00 0A 00 06 07 00 00 00 01
```
